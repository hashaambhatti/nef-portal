# NEF Portal - fixes (backend 1.3.0, dashboard 2.2.0)

Every issue from the review "NEF Portal - Issues List aur Deployment Guide",
with what was changed. IDs match that review.

## Critical - security

| ID | Fix | Files |
|---|---|---|
| S1 | Public signup can only create **Teacher** accounts; the `role` field is gone. First Admin via `npm run create-admin`; more Admins via `POST /api/users` (Admin only). Role dropdown removed from the signup page. | `validators/auth.validator.js`, `services/auth.service.js`, `scripts/create-admin.js`, dashboard `js/pages/auth.js` |
| S2 | `GET/POST/PUT /api/users` are Admin-only. New `GET/PUT /api/users/me` for one's own account (role can never be changed there; email/password change needs the current password). An Admin cannot remove their own Admin role, and at least one Admin must remain. | `routes/users.routes.js`, `services/auth.service.js` |

## Critical - frontend/backend mismatch

| ID | Fix | Files |
|---|---|---|
| F1 | `USE_MOCK_API: false`. API URL switches automatically: localhost -> `http://localhost:3000/api`, otherwise `PRODUCTION_API_BASE_URL`. Demo data is only seeded in mock mode. | `config.js`, `js/api/mockData.js` |

## Also fixed (found while testing)

- Logout did not clear the stored token; it now calls `POST /auth/logout` and clears the session.
- An expired or revoked session now sends the user back to the login page instead of showing empty pages.
- A page that fails to load shows an error message instead of a blank screen.
- `exportFilteredTeachers` / `exportFilteredSchools` were referenced but never defined, which threw an error every time those pages loaded; the broken references were removed.
- Schools, teachers and dashboard pages crashed when a record had an empty field (e.g. `schoolStatus` NULL); string checks are now null-safe.
- Renaming a school keeps its students attached (students store the school name).
- JSON parse errors return 400 instead of 500.

## Database change

New databases: `npm run db:setup`. A database created from the old
`schema.sql` needs `db/migrations/001_token_version.sql` once.

## Not verified here

`npm install` and MySQL were not available in the environment used for
these fixes, so the backend was tested with a fake database and the
dashboard against a fake API that uses the real validators. Before go-live,
run it once against a real MySQL: `npm run db:setup`, `npm run create-admin`,
`npm run dev`, then click through login, enrollment, attendance and
promotion.
