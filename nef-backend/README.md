# NEF Backend

Node.js + Express + MySQL API for the NEF School Portal dashboard
(`nef-dashboard`). Version 1.3.0 - security and deployment fixes (see
`CHANGES.md`).

## 1. Requirements

- Node.js 18 or newer
- MySQL 8.0.16 or newer (local, or a managed service such as Aiven)

## 2. Local setup

```bash
npm install
cp .env.example .env        # then edit .env (DB details, JWT_SECRET)
npm run db:setup            # creates all tables from db/schema.sql
npm run create-admin        # creates the first Admin account (asks for name/email/password)
npm run dev                 # starts the API on http://localhost:3000
```

Check it: open `http://localhost:3000/health` - it should show
`{"status":"ok","database":"ok"}`.

Then open the dashboard (`nef-dashboard/index.html`) with VS Code Live
Server. When the page runs on `localhost` / `127.0.0.1` it talks to
`http://localhost:3000/api` automatically. If Live Server uses a port other
than 5500, put that exact origin in `CORS_ORIGIN` and restart the backend.

Run the tests (no database needed):

```bash
npm test
```

## 3. Accounts and roles

- **Admin accounts** are created only with `npm run create-admin` or by an
  existing Admin through `POST /api/users`. Public signup can never create an
  Admin.
- **Teacher accounts** are created through the signup page (one transaction:
  teacher profile + account + school teacher count), or by an Admin.
  Set `ALLOW_SIGNUP=false` to turn self-registration off.
- A Teacher only sees and changes students, guardians and attendance of
  **their own school**, and sees other teachers without CNIC / phone / bank
  details. Only an Admin can change a teacher's school or employment status.
- Logout and password changes revoke the user's existing tokens.

## 4. API

All routes are under `/api`. Except the three public ones, every route needs
`Authorization: Bearer <token>`.

| Method | Path | Who | Notes |
|---|---|---|---|
| POST | /auth/login | public | `{ email, password }` -> `{ token, user }` (user includes `teacherId`) |
| POST | /auth/signup | public | Teacher only: `{ name, email, password, teacherProfile }` |
| GET | /schools/public | public | `[{ schoolCode, name }]` for the signup form |
| POST | /auth/logout | any | revokes the token |
| GET / PUT | /users/me | any | own name/email/password; email or password change needs `currentPassword` |
| GET / POST / PUT | /users | Admin | list, create (any role), bulk edit by `id` |
| GET | /students | any | Teacher: own school only |
| POST | /students | Admin, Teacher | enrollment; optional `guardian` object; ids generated by the server |
| PUT | /students | Admin, Teacher | grade promotion: `[{ studentId, class, result, passOutDate }]` |
| PUT | /students/:id | Admin, Teacher | Teacher: own school only, cannot move schools |
| DELETE | /students/:id | Admin | keeps a guardian shared with a sibling |
| GET | /guardians | any | Teacher: own school only |
| PUT | /guardians | Admin | bulk upsert |
| PUT | /guardians/:id | Admin, Teacher | Teacher: own school only |
| GET | /teachers | any | Teacher: others without CNIC/phone/bank |
| POST | /teachers | Admin | `teacherId` optional (generated) |
| PUT | /teachers/me | Teacher | own profile, not school/status |
| PUT / DELETE | /teachers/:id | Admin | delete refuses while the teacher has students |
| GET | /schools | any | |
| POST | /schools | Admin | optional `building` object; codes generated |
| PUT / DELETE | /schools/:code | Admin | delete refuses while teachers/students remain |
| GET / PUT | /buildings | any / Admin | bulk |
| GET / PUT | /classes | any / Admin | bulk |
| GET / PUT | /attendance | any / Admin, Teacher | Teacher: own school only |
| GET | /health | public | `503` if the database is unreachable |

Errors are JSON: `{ "message": "...", "errors": [{ "field", "message" }] }`.

## 5. Deploying (Render + Aiven MySQL)

1. **Database.** Create a free MySQL service on aiven.io. From its Overview
   page copy host, port, user, password and the **CA certificate**.
2. **Backend.** On render.com: New -> Web Service -> this repo.
   Build command `npm ci --omit=dev`, start command `npm start`, health check
   path `/health`. (Or use the included `render.yaml` Blueprint.)
3. **Environment variables** on Render:

   | Variable | Value |
   |---|---|
   | `NODE_ENV` | `production` |
   | `JWT_SECRET` | 32+ random characters (`openssl rand -hex 32`) |
   | `CORS_ORIGIN` | the dashboard's exact URL, e.g. `https://nef-dashboard.onrender.com` |
   | `MYSQL_HOST`, `MYSQL_PORT`, `MYSQL_USER`, `MYSQL_PASSWORD` | from Aiven |
   | `MYSQL_DATABASE` | `defaultdb` (Aiven's default) or a database you created |
   | `MYSQL_SSL_CA` | the Aiven CA certificate text |

   Do not set `PORT`; Render provides it. The server refuses to start if
   `JWT_SECRET` or `CORS_ORIGIN` is missing or weak, and prints why.
4. **Create tables and the first Admin.** From your own computer, with a
   `.env` holding the same Aiven values:
   ```bash
   npm run db:setup
   npm run create-admin
   ```
   (Or Render's Shell tab, on paid plans.)
5. Open `https://<your-backend>.onrender.com/health` -> `{"status":"ok","database":"ok"}`.
6. Deploy the dashboard (see its README) and log in with the Admin account.

Render's free web service sleeps after 15 minutes without requests; the
first request after that takes about a minute. Use a paid instance for real
users.

**Vercel (no credit card)** instead of Render: vercel.com -> Add New ->
Project -> import the repo, set **Root Directory** to `nef-backend`, add the
same environment variables, Deploy. Vercel finds `src/app.js` and runs the
Express app as a serverless function (`server.js` is not used there; the
config check runs in `app.js`). The pool size defaults to 3 on Vercel.

**Docker** instead: `docker build -t nef-backend .` then
`docker run --env-file .env -p 3000:3000 nef-backend`.

## 6. Upgrading a database created by an older version

Run `db/migrations/001_token_version.sql` once (adds `users.token_version`
and an index). Existing users then need to log in again.

## 7. Project layout

```
src/
  server.js            entry point; checks configuration before starting
  app.js               middleware (helmet, CORS, rate limits) + routes + /health
  config/env.js        all settings, validated at startup
  config/db.js         mysql2 pool (SSL, dateStrings)
  middleware/          authenticate (DB-checked JWT), authorize, validate, errors
  routes/ controllers/ services/ validators/
  utils/ids.js         next TCH/STD/GRD/SCH/BLD id (MAX + 1)
  utils/scope.js       Teacher -> own-school checks
scripts/               setup-db.js, create-admin.js
db/schema.sql          the full schema
tests/                 node:test suites (fake DB, no MySQL needed)
```
